# fpkstudio

飞牛 fnOS 的 fpk 打包工作台：在浏览器里浏览、编辑 fpk 项目目录，调用官方 `fnpack` 打包，支持多架构分别出包。

它是 [fnpackup](https://github.com/snltty/fnpackup) 的重写版本——保留了「把 fpk 包目录做成可视化编辑器」这个核心价值，去掉了静态托管，并把交付形态从
「Docker 容器 + 特权 + TCP 端口」换成了「单文件静态二进制 + 非 root + 只监听 unix socket」。

## 与 fnpackup 的主要差异

| | fnpackup | fpkstudio |
|---|---|---|
| 后端 | .NET 8，跑在容器里 | Go 1.27，单文件自包含二进制 |
| 前端嵌入 | 编译进单文件 | `go:embed`，同一份产物可挂任意 baseURL |
| 监听 | TCP 1069 / 10699 | **只有 unix socket**，不占任何 TCP 端口 |
| 鉴权 | 无（端口直连可绕过 CGI 登录态） | 无（只能由 socket 文件权限兜底） |
| 运行身份 | 容器内 root（`--privileged`） | 普通用户，不需要任何特权 |
| 路径 | 硬编码容器内路径（`/app/...`、`/usr/share/...`） | 全部来自环境变量 |
| 打包是否改项目文件 | 会（原地改 manifest、覆盖 app/server） | **不会**，在暂存副本里操作 |
| 静态托管 | 有 | 无 |
| 编辑界面 | 每个文件一个弹窗 | 标签页：首页固定 + 每项目一个标签 + 项目内固定子标签（文件 / 总览 / 快捷设置 / 图标）+ 文件子标签 |

## 环境变量

所有路径都由环境变量给出，程序不假设任何部署形态。日志、PID、socket、临时文件统一落在**数据目录**下。

| 变量 | 默认值 | 说明 |
|---|---|---|
| `FPKSTUDIO_DATA_DIR` | `$XDG_DATA_HOME/fpkstudio` 或 `~/.local/share/fpkstudio` | 数据根目录 |
| `FPKSTUDIO_PROJECTS_DIR` | `$FPKSTUDIO_DATA_DIR/projects` | 项目根目录（项目列表与文件树的沙箱根），可以在数据目录之外 |
| `FPKSTUDIO_OUTPUT_DIR` | `$FPKSTUDIO_DATA_DIR/output` | 打包产物目录，可以在数据目录之外 |
| `FPKSTUDIO_SOCKET` | `$FPKSTUDIO_DATA_DIR/run/fpkstudio.sock` | unix socket 路径（上限 100 字节，超了会明确报错） |
| `FPKSTUDIO_BASE_URL` | `/` | 访问前缀，例如 `/app/fpkstudio` |
| `FPKSTUDIO_FNPACK` | `fnpack`（走 PATH） | fnpack 可执行文件 |
| `FPKSTUDIO_LOG_LEVEL` | `info` | `debug` / `info` / `warn` / `error` |
| `FPKSTUDIO_LOG_RING` | `5000` | 内存里保留的日志条数 |
| `FPKSTUDIO_TRIM_SOCKET` | `/var/run/trim_open_gateway_apiscope.socket` | 飞牛开放 API 的 socket（由系统提供，覆盖它只是为了在没有 fnOS 的环境里调链路） |
| `FPKSTUDIO_TRIM_APP` | `fpkstudio` | 开放 API 请求体里的 `appName`，要和 fpk 的 `manifest.appname` 一致 |

`FPKSTUDIO_PROJECTS_DIR` 与 `FPKSTUDIO_OUTPUT_DIR` 都只是**默认值**：两者都能在界面的
设置弹窗里改成用户授权的目录（见 [飞牛开放 API 接入](#飞牛开放-api-接入)），改过之后就
记在数据目录的 `state.json` 里，环境变量只在没设置时生效——也就是说优先级是
**界面设置的授权目录 > 环境变量 > 数据目录下的默认值**。

两个环境变量指到**同一个路径**时保项目目录：`FPKSTUDIO_OUTPUT_DIR` 按「没设置」处理、
输出目录退回 `$FPKSTUDIO_DATA_DIR/output`，设置弹窗里会标注它被忽略了。两个目录混在
一起的话，产物既算项目产物又算输出产物（列表里同一个文件出现两次）、复制还等于复制到
自己身上，谁都说不清它到底在哪。

界面上不允许把两个槽设成同一个目录（直接报错）。默认值这一侧还有一层兜底：项目目录可以
被指到数据目录下的任何位置，包括 `output/`——那正是输出目录的默认值，退回之后还是同一个。
这时**不拒绝启动**，按「没有单独的输出目录」处理（不重复复制、产物只按项目目录列一次），
因为把部署配置判成错误只会让服务起不来，而实际后果只是多余的复制。

### 数据目录布局

```
$FPKSTUDIO_DATA_DIR/
├── projects/            项目目录（fpk 包目录）
│   └── <appname>/
│       ├── manifest  config/  cmd/  wizard/  app/  i18n/
│       └── building/
│           ├── settings.json        打包偏好（架构选择、落地目录…）
│           └── platform/<架构>/      各架构的产物，打包时复制到 app/server
├── output/              打包产物（FPKSTUDIO_OUTPUT_DIR）
├── logs/fpkstudio.log   运行日志（滚动 8MB × 3）
├── state.json           用户在设置里改过的目录（项目根目录 / fpk 输出目录）
├── run/fpkstudio.sock
├── run/fpkstudio.pid
└── tmp/                 暂存与 fnpack 的 TMPDIR
```

`projects/` 与 `output/` 只在没人改过目录设置时才是项目 / 产物的实际位置。
项目根目录可以被指到数据目录之外（用户从飞牛文件选择器授权进来的目录），那时
`projects/` 就只是个空壳。

## 快速开始

一条 `make` 就够了：构建前端 → 复制进 `backend/embed` → 编译后端 → 清掉 `embed`，
最终在**项目根目录**得到 `./fpkstudio`。

```bash
make                    # 默认 dev 构建（不 strip），版本 1.0.0
make release V=1.0.1    # release 构建（strip 符号），版本可覆盖
make test               # 后端单元测试
make clean              # 删除二进制与 embed 目录
```

```bash
# 运行
FPKSTUDIO_DATA_DIR=/srv/fpkstudio \
FPKSTUDIO_BASE_URL=/app/fpkstudio \
FPKSTUDIO_FNPACK=/usr/local/bin/fnpack \
./fpkstudio
```

启动日志只有一行（路径、socket、base url 这些运行参数不再往里灌——它们每次启动都
一样，只会把日志弹窗里真正要看的「刚才发生了什么」淹掉）：

```
fpkstudio 1.0.0 已启动
```

要看解析后的配置，用 `-paths`（不启动服务）：

```bash
./fpkstudio -paths
```

## 访问方式

只监听 unix socket，没有「打开端口就能用」这一说。两种接法：

**1. 直接调 API**

```bash
curl --unix-socket /srv/fpkstudio/run/fpkstudio.sock \
     http://localhost/app/fpkstudio/api/system/info
```

**2. 用 nginx / Caddy 反代给浏览器用**

```nginx
location /app/fpkstudio/ {
    proxy_pass http://unix:/srv/fpkstudio/run/fpkstudio.sock;
    proxy_http_version 1.1;
    proxy_set_header Connection "";
    proxy_buffering off;   # 构建日志走 SSE，必须关缓冲
}
```

`FPKSTUDIO_BASE_URL` 要和反代的 location 对上（上面这个例子就是 `/app/fpkstudio`）。
同一份前端产物可以挂任意前缀：服务端返回 index.html 时会按实际前缀注入 `<base href>`
和运行时配置，换挂载点不需要重新构建。

> 应用自身不做鉴权（按需求）。**唯一的访问控制就是 socket 文件的权限（0660）**，
> 以及你套在外面的反代。不要把 socket 暴露给不可信的用户或进程。

## 开发

```bash
make          # 完整构建，产出 ./fpkstudio
make test     # go test ./...
make clean    # 清产物
```

`make` 之外还有两个常用入口：

```bash
cd backend  && go vet ./...          # 后端静态检查（需要 GOCACHE/TMPDIR，见下）
cd frontend && npm run typecheck     # 前端类型检查
cd frontend && npm run check         # 语言包 + 向导回写 + 取景框几何 + 命名与文本格式 + 多选标签 + 分页排版 + 语义路径 + 文件管理器 store + 日志 store
cd frontend && npm run dev           # 只起 Vite 开发服务器
```

关于 `npm run dev`：**它连不到后端**。后端只监听 unix socket，浏览器的 fetch
打不过去，所以 `dev` 只适合调纯 UI（布局、样式、组件）。要连后端调试，
走 `make && ./fpkstudio`，再用 nginx 把某个 location 反代到 socket（见上一节），
这样拿到的是完整链路。想临时桥一下直接在浏览器里点，`socat` 更省事：

```bash
FPKSTUDIO_DATA_DIR=/tmp/fpkstudio-data FPKSTUDIO_FNPACK=/bin/true ./fpkstudio &
socat TCP-LISTEN:18080,fork,reuseaddr UNIX-CONNECT:/tmp/fpkstudio-data/run/fpkstudio.sock &
```

没有 fnpack 也能验界面：直接在 `$FPKSTUDIO_DATA_DIR/projects/` 下手搓一个项目目录即可
（最少要有 `manifest`，且 `appname` / `version` / `platform` 三个键得齐）。

**给 AI / 自动化助手的操作手册在 [AGENTS.md](AGENTS.md)**：命令、目录、约定、
「已经踩过的坑」都收在那里，改代码前先读一遍。

## 飞牛开放 API 接入

应用跑在飞牛里时可以用系统的文件授权能力：让用户在应用自己的页面里选一个目录或文件，
系统把它的 ACL 授权给应用用户（应用服务以独立的应用用户运行，没有这条授权就读不到
用户的存储空间）。用到三个能力：

| Scope | 用来做什么 | 谁调 |
|---|---|---|
| `trim.file.userAccess` | 选目录 / 选文件并完成授权（`pickUserFile`）、查询与删除已授权目录 | 前端 JS SDK + 后端 |
| `trim.file.userAcl` | 导入前按当前用户检查目标文件是否可读 | 后端 |
| `trim.file.path` | 把 `/vol1/...` 转成用户看得懂的语义路径 | 后端 |

分工是硬性的，不是取舍：

- **前端**用 `@trimjs/web-app` 的 JS SDK 拉起选择器（这类能力必须有用户操作，且只能在
  宿主页面里调）。
- **后端**用开放 API（`POST /api/v1/trimapp`，只挂 unix socket）查授权、查权限、转路径。
  官方文档明确要求后端接口只能由服务端调、token 不能下发到浏览器，所以前端一律走
  `/api/trim/*` 转一手。

token 每次调用时从环境变量 `TRIM_API_TOKEN` 现读——系统在重新注册 / 重装 / 运行环境
变化后都会换新值，持久化下来只会拿到过期的那一个。当前用户取统一网关转发的
`X-Trim-Userid`（网关只在校验过登录态之后才转发这组 Header）；没经过网关时退化成后端
进程自己的 uid，单用户场景够用，也让这套接口在没有 fnOS 的环境里能跑通链路。

**这些能力要在 fpk 包的清单里声明才生效。** 这个仓库的交付形态是单文件二进制、没有应用包，
所以打包成 fpk 时要自己带上：

```
# manifest
micro_app=true
```

```json
// config/resource
{ "api-scope": ["trim.file.userAccess", "trim.file.userAcl", "trim.file.path"] }
```

`micro_app=true` 决定页面是否按微应用加载（不声明时 JS SDK 根本起不来）；声明
`api-scope` 只是接入前提，具体能访问哪个目录仍由用户授权、管理员设置和 token 决定。
`config/resource` 的编辑器里已经内置了这几个授权项，打开开关即可。

### 界面上用到的地方

- **首页右上角「设置」**：占视口 90% 高、垂直居中的弹窗，正文自己滚（标题与「关于」
  不跟着滚走），遮罩带一层背景模糊，弹窗打开时锁住页面滚动。内容是主题切换 +
  两个目录槽（项目根目录、fpk 输出目录）+ 关于。
  两个槽各只能设一个目录，且只能来自文件选择器的授权；每槽显示 `trim.file.path` 转出来的
  展示路径（**转换失败才回落显示 `/vol1/...` 原始路径**，并另给一句失败原因），界面上不展示
  ACL 标签；每槽右侧有「选择 / 更换目录」和文件夹按钮（在文件管理器里打开该目录）。
  「取消设置」会删掉该目录的授权，并把这一槽还给环境变量给的默认目录。
- **换目录的顺序是有讲究的**：先完成新目录的授权与切换（配置落盘、后端切过去），
  **再**删旧目录的授权。反过来的话，用户一取消选择、或者选择器直接报错，旧授权已经没了
  而配置里还写着它，应用会突然读不到自己的项目目录。删旧授权失败只记一条警告——
  它留在系统里只是不干净，不该挡住换目录这件事。
- **语义路径失败要说出来**。`trim.file.convertPath` 的返回结构**与文档不一致**：文档写
  `{"status":0,"result":[…]}`，实测的系统直接回 `[{path,semanticPath}…]`。所以
  `internal/trimapi` 三种形态都认（还有「只回一串展示路径」的兜底），`data.status` 非 0
  也算失败；`language` 是必填项且走请求体（查询串会被反代丢掉）。失败时弹窗给一句原因，
  而不是默默退回显示 `/vol1/...`——「什么都没显示」是最难查的表现。
- **产物可以直接在文件管理器里打开**：产物行右侧的文件夹按钮调 SDK 的
  `openFileManager`（官方「页面路由」，无 scope 要求），目录由产物自己的绝对路径算出，
  不依赖 `/api/system/info` 里的 `outputDir`（换过目录之后它是旧的）。
- **用户取消选择不算错误**：宿主机在用户直接关掉选择器时返回 `code: 1` +
  `msg: "Operation failed"`，没有业务码也没有可读原因。`trim/sdk.ts` 把它与「成功但
  没返回路径」一起归一成空数组，界面给一句「已取消目录授权 / 已取消导入」，而不是弹
  一句「调用飞牛接口失败（1）」。
- **项目根目录真的会生效**：换成授权目录之后，项目列表、文件树、创建 / 导入 / 打包都读写
  那个目录，数据目录里只留日志、暂存和配置（见「实现上值得说明的几处」里的跨沙箱复制）。
- **导入 fpk**：在「选择文件」旁边多了「选择飞牛文件」，走 `pickUserFile` 让用户在飞牛的
  存储空间里挑 `.fpk`，选完由后端按路径读文件导入。浏览器拿不到 `/vol1/...` 这种路径，
  选择器只负责把路径授权给应用。
- **独立浏览器页面**（没有宿主桥，例如 `socat` 桥出来自己点）里这些入口一律置灰并说明
  原因。官方推荐的另一条路是 `openAppAuth` + `redirectUri` 回调页，它要求应用挂在统一
  网关下、回调页与原页面同源，本项目没有这条链路，所以选择「明确告诉用户去飞牛里打开」，
  而不是给一个点了就报错的按钮。

### 深色模式

`html.dark` 是唯一的开关：Tailwind 的 `dark:` 变体（在 `style.css` 里用
`@custom-variant dark` 改成认这个类）与 Element Plus 的暗色变量挂在同一个类上，由
`stores/theme.ts` 统一切换。「跟随系统」在宿主里跟的是飞牛主题（`$on('os/theme')`），
在独立浏览器里跟的是 `prefers-color-scheme`，两条都会实时响应。主题记在 localStorage，
不进 `state.json`（它是界面偏好，不是部署配置）。

## 前端

Vue 3.5 + Pinia 4 + Tailwind 4 + TypeScript 6.0.2 + Vite 8，UI 组件用 Element Plus 2，
代码编辑器 CodeMirror 6，构建日志弹窗用 xterm 6，路由 vue-router 5，国际化 vue-i18n 11。

几个刻意的设计：

- **标签页而不是弹窗**：首页「项目管理器」是固定标签；每打开一个项目占一个标签；
  项目内的子标签分两组，前面是固定标签——**文件**（只在标签页模式下出现，见下）、
  **总览**（打包设置 + manifest 预览）、**快捷设置**、**图标**，后面是打开的文件。
  固定标签钉在标签栏最左边、不参与横向滚动，打开的文件再多也不会把它们挤出去。
  所有编辑都在标签里完成，打开的文件全部保持挂载，切标签不会丢未保存的内容。
- **关掉项目标签 = 退出这个项目**：它在内存里的那份状态（文件树、打开过的文件、打包
  配置、产物）跟着一起丢，下次打开重新读盘。项目就躺在磁盘上，应用外面完全可能被换过
  （手动换掉文件、从别处导入一份、删掉再建一个同名的）——留着旧状态的表现是「关掉再
  打开还是老内容，只有手动刷新才更新」，换个同名的项目甚至会把上一个项目的文件列出来。
  收口在 `ProjectTab` 的卸载钩子（`workspace.forget`）上，所有关闭入口最后都是它被
  卸载；正因为如此，「关闭其他标签」也要像单关一个标签那样先问一句未保存的改动。
- **文件管理器有两种模式**（每个项目各自记在 localStorage，默认左栏文件树）：
  - **左栏文件树**（默认）：侧边栏里的树，工具栏只有刷新 / 全部展开-收起 / 切到标签页
    模式 / 在文件管理器里打开项目目录四个按钮——新建文件、新建目录、上传都收进了节点的
    菜单里，因为「新建到哪一层」得先看节点。行里不显示文件大小（树很窄，大小既挤又难对齐）。
    「新建文件 / 新建目录 / 上传文件」只出现在**目录**（含项目根）的菜单里：文件上
    放这几项，点了其实是作用在它的父目录，和用户看着的那一行对不上。压缩包多一项
    「解压」。
    分隔线只有 1px、手指点不中，所以顶栏右侧还有一个**吸在分隔线上的手柄按钮**
    （`Rank` 图标，按下去就是拖动，事件抛给 `ProjectTab`，和拖那条线是同一段逻辑；
    按钮上带 `touch-none`，否则触屏会把 `pointermove` 当成滚动手势收走）。
    左栏宽度可以拖着改（记在 localStorage），上下限是 **180 / 窗口宽度的一半**：
    上限每次拖都现算，写死一个像素值在窄窗口上等于「能把编辑区挤到只剩两百来像素」，
    窗口拉宽之后那个上限又白白浪费；从 localStorage 读回来时也按当前窗口钳一次
    （同一份宽度可能是在一块大屏上设的）。
  - **标签页模式**：文件管理器变成项目里的一个固定子标签（**文件**，钉在总览左边），
    侧边栏整块让出来。顶栏是常见文件管理器那一套——后退 / 前进 / 刷新、新建 / 上传、
    列表 / 网格、切回左栏模式，末尾隔一组是「在文件管理器里打开项目
    目录」（和文件树顶栏是同一个动作，两处共用

    不消失，而且触屏上根本没有「移开」这个动作——点一下就一直挂着挡住内容。浏览器原生

  - **重命名不会覆盖同名文件**：目标已经存在时直接拒绝（前端在现拉的目录列表里先判一次，
    后端 `fsx.Rename` 再挡一道）。`rename(2)` 默认会把同名文件顶掉，而用户只是想改个名，

    「改个文件名，编辑框空了，随手敲一个字保存，原内容就没了」。
- **解压**：菜单里的「解压」调后端 `/api/fs/extract`，后端再调系统的 `tar` / `unzip` /
  `gzip`（`fsx.Extract`），解到压缩包**自己所在的目录**。认这些后缀：`.tar` / `.tar.gz` /
  `.tgz` / `.tar.bz2` / `.tbz2` / `.tbz` / `.tar.xz` / `.txz` / `.tar.zst` / `.tzst` / `.gz` /
  `.bz2` / `.xz` / `.zst` / `.zip`，前端用同一套判据决定菜单项出不出现。tar 的命令**不带压缩
  参数**——GNU tar 读归档时按魔数自己认 gz / bz2 / xz / zst，一个命令覆盖全部 tar 变体；
  单个文件的 `.gz` / `.bz2` / `.xz` / `.zst` 交给对应的解压工具；**zip 也交给系统的
  `unzip`**——和 tar 一样「跟用户在终端里敲一遍」的行为，边角情况（属性位、跨平台名字、
  加密包）不用自己维护。`unzip` 必须带 `-o`：不给的话它遇到同名文件会停下来等 stdin，
  而服务进程没有终端，请求会一直挂着。
  同名文件一律**跳过、不覆盖**，跳过的数量会在提示里说清楚——解压最常见的情形是往一个
  已经存在的目录上补内容，静默覆盖用户的文件是不可逆的。归档里带绝对路径或 `..` 段的
  会被整体拒绝（tar 自己对越界名字只给警告、退出码还是 0；`unzip` 更省事，它把越界名字
  截断成安全名字照写不误、退出码给 1——两者都挡不住，所以解压前先自己列一遍成员名：
  tar 用 `tar -t`、zip 用 `unzip -Z1`；zip 的反斜杠分隔同样按 `/` 归一后再判）。
  归档里的**符号链接一律不还原**（`fsx.sanitizeExtracted`，非普通文件也一样）：链接可以指向归档外面，
  `ln -s /etc/passwd leak` 留在项目里既点不进去，又会被后面的复制 / 打包顺着读出去；
  丢掉的数量会一并提示。
- **移动布局**：窄屏（< 768px，和 Tailwind 的 `md` 断点一致）自动切过去，也可以在

  用标签页模式、不显示文件树，项目内只有**文件 / 总览 / 快捷设置 / 图标**四个标签；
  打开文件时在项目标签栏下面新开一个子页面（盖住整个项目区，包括那四个标签），
  编辑器工具栏最左边那个左箭头（只有图标，旁边就是文件名）等同于关掉这个文件标签——
  未保存的提醒和桌面上点标签上的 ×
  是同一段逻辑（`components/project/useCloseFile.ts`），两处各写一份迟早有一边忘了问。
  **后退回到「打开这个文件之前停在哪」**（`ProjectState.fileReturnTab`）：从「文件」
  标签点进去的就退回「文件」标签，而不是无脑退回总览。
  编辑器工具栏分两组（后退 + 文件名 / 其余按钮），窄屏放不下时**整组按钮换行**，
  而不是从中间随便断。
  表单在窄屏下换一种排布（`style.css` 的 `.form-stack`）：桌面那套「固定宽度的右对齐
  标题 + 控件」会把控件挤得没地方，窄屏改成标题一行、控件一行、标题左对齐；开关这类
  小控件不分行。规则放在 utilities 层——级联层比选择器权重更硬，放 components 层会被
  元素上的 Tailwind 工具类压过去（这个坑踩过一次）。manifest、入口配置、运行身份这几份
  表单在桌面就是这套竖排（见上面两节），窄屏下 `form-stack` 做的只是把「一行一组」拆回
  一行一个——**拆开后开关也跟着竖排**（它们是多列行里的单元格，`form-row-inline` 那套
  「小控件不分行」在这几份表单里不适用）。运行身份只有一列，桌面和窄屏是同一种排布，
  所以它连 `form-stack` 都不挂。
  拆行的顺序就是 DOM 顺序，所以**桌面上的配对要按窄屏的阅读顺序往 DOM 里写**：manifest
  的开发者 / 发布者那组靠 `grid-flow-col` + 两行折成两列，为的就是让窄屏竖排出来是
  「开发者 → 开发者链接 → 发布者 → 发布者链接」。
  源码 / 生命周期脚本编辑器（CodeMirror）在移动布局下放大到 16px。
  **整块应用钉在「可视视口」上**（`utils/viewport.ts` 把可视视口的高度和上沿偏移写进
  `--vv-height` / `--vv-top`，`style.css` 的 `#app`、弹窗遮罩和弹窗本身都按它定位）——
  手机上点开输入框，键盘盖住底部，正在编辑的那一行就看不见了；而 iOS 还允许把可视视口
  拖着平移，只缩高度的话下面会露出空白（「拖到底还能继续拖」）。钉住之后可视的那一块
  永远被应用盖满。它跟的是「可视视口」而不是布局开关，所以桌面 / 移动两种模式都管用
  （桌面上可视视口就是整个视口，等于没写）。
  移动端还有两处小差别：**输入类控件的字号提到 16px**——iOS Safari 聚焦小于 16px
  的输入框会自动把整个页面放大而且不缩回去，`user-scalable=no` 从 iOS 10 起被忽略，
  只能靠字号挡；关闭按钮见下面「关闭按钮」那条。
- **桌面上的标签页和按钮统一 14px**（首页、弹窗先不动）。主标签本来就是 `text-sm`，
  文件子标签从 13px 提到 `text-sm`；带字的按钮显式给 `size="default"`（全局配的是
  `size: 'small'` = 12px，`el-tag` 还要挂 `class="text-sm"`），**只有图标**的按钮保持
  `size="small"`。
- **关闭按钮只有一种形态：红色小叉**（项目标签 / 文件子标签 / 入口标签 / 弹窗）。
  标签上那三个走 `style.css` 的 `.close-x`（颜色取 Element Plus 的危险色变量，深浅主题
  各自有值），弹窗右上角（`el-dialog` 与 `el-message-box`）在同一处覆盖成红色——选择器
  要和 Element Plus 自己的同权重、写在它之后，hover / focus 两条也必须一起覆盖，否则
  鼠标一上去又变回主题色。
  显示时机走 `.hover-reveal`（挂在关闭图标上、父元素挂 `.group`），**不要**写
  `opacity-0 group-hover:opacity-100`：Tailwind 4 给 hover / group-hover 变体自带
  `@media (hover: hover)`，没有指针悬停的设备（触屏平板）上那条规则永远不生效，元素就
  一直停在 `opacity-0`「永远不显示」。`.hover-reveal` 反过来写：默认常显，只有真的能
  悬停的设备（`@media (hover: hover)`）才收起来、悬停或聚焦时再出现。
- **项目内的固定子标签**（**打开项目默认停在「快捷设置」**——改 manifest / 权限 /
  脚本是打开项目之后最常做的事，总览更多是打包时才看）。这三个面板（总览 / 快捷设置 /
  图标）的字号和编辑器里的表单对齐，统一 14px：文本写 `text-sm`，带字的控件显式给
  `size="default"`（Element Plus 全局配的是 `size: 'small'` = 12px，`el-tag` 的
  `--el-tag-font-size` 更是写死 12px，所以它得挂 `class="text-sm"` 而不是靠 size）；

  - `总览`：多架构发布、打包结果、产物列表（窄屏下每行的大 / 时间 / 目录 / 下载会
    整体下移一行、右对齐，别把产物名挤没）。**「多架构发布」开关在内容框里**（不在标题栏）：
    它控制的就是下面那一片内容，开关和它管的东西放一起，标题栏只留标题和刷新。
    右侧是 manifest 预览，宽屏下两列**各占一半**（清单那列原来是固定 24rem，宽屏上偏窄）——逐行取
    原文、按最长键补齐、等宽字体渲染成对齐的 `key = value`，`checksum` 不参与预览
    （每次打包都会变），长值折三行、点一下展开。预览跟着 manifest 编辑页的保存同步；
    宽屏（`lg`）时预览列跟着一起粘在顶部（`lg:sticky`）。
    这一页就是原来的「打包」页。打开「多架构发布」时会检查 `building/platform/`：
    缺 `arm` / `x86` 就补建（只建目录、不自动勾选，空目录打出来的包是空的），
    与创建 / 导入项目时预置的目录一致。
    打包前还会拦一道官方约定：项目有 `i18n/` 目录却缺 `en-US` 时直接报错、不发打包
    请求（后端 `Pack` 同样拒绝，界面这层只是把原因说明白、少一趟注定失败的请求）。
  - `快捷设置`：把最常改的文件做成快捷入口，点一下就在子标签里打开，已经打开的
    直接切过去。带桌面入口的项目才有「桌面入口」，docker 应用才有 docker-compose。
    文件不存在时（向导、生命周期脚本常常是空的）按空内容打开，工具栏显示「未创建」
    而不是「未保存」，编辑后保存才落盘、父目录随之建出来。
    「国际化」这一组里，有 `i18n/` 目录却没有必须的 `en-US` 时会在标题下压一条提示
    （官方约定：有 `i18n/` 就必须提供 `en-US`，缺了应用在英文环境下文案全是空的）。
    图标与环境变量不在这里——前者有专门的图标页，后者跟着生命周期脚本走。
    几组卡片用多列布局流式排布（宽屏两列、窄屏一列），而不是网格对齐：

  - `图标`：进页面先把项目里已有的应用大图标载进取景框当底图（包根的 `ICON_256.PNG`，

- **上传与导入都能取消**：上传 / 导入进行中，工具条（或导入面板）上会出现进度与
  「取消」，点了立刻 abort；服务端跟着停、写了一半的文件删掉。单个请求上限 1G，
  超了会明确回一句「超过上限」，不会写一个半截文件进去。
- **复制 / 剪切 / 粘贴**：右键节点、或用行尾那个低调的「···」出菜单。复制和剪切
  **只记路径**（剪贴板，两种模式共用），粘到哪个目录由你选：在目录上粘贴就是粘进去，
  在文件上粘贴就落到它的父目录。剪切中的那一行会淡一半；**粘一次就清空剪贴板**
  （复制和剪切都是）——它在这里只是「搬一次文件」的中转，留着反而容易在切了几层目录
  之后粘错地方。**剪切到同一个目录**等于什么都没做（剪贴板留着）。目标重名时复制自动加
  「副本」、**绝不覆盖**，剪切则直接拒绝（改名到一个
  已存在的路径上，轻则报错重则覆盖，不如让用户自己决定）。菜单贴近窗口右 / 下边缘时会
  自己收回来，不会被切掉。
- **上传带进度**：文件树的目录菜单和标签页顶栏都能上传（同名直接覆盖），上传期间是
  一条全屏进度提示（百分比来自 XHR 的 `upload.progress`），结束无论成败都关掉它并给
  一句结果。
- **主题、语言、界面与目录设置**：首页右上角的「设置」按钮打开弹窗，主题（浅色 / 深色 /
  自动）+ 语言（中文 / English / 自动）、界面形态（自动 / 桌面 / 移动）与两个授权目录槽
  都在这里（都是「标题一行、按钮一行」），

- **界面语言三档：中文 / English / 自动**（设置弹窗里，和主题一样是「标题一行、按钮一行」；
  默认跟随系统，按钮上写「自动」）。偏好记在 localStorage（`fpkstudio.locale`，和主题、显示方式一样不进
  后端状态文件），三处要一起换：vue-i18n 的 locale、`html lang`（不一致时屏幕阅读器和
  翻译插件会认错）、以及 Element Plus 的语言包。**Element Plus 的全局配置对象必须是
  `reactive` 的**（`i18n/index.ts` 的 `elementOptions` 交给 `app.use`）：切语言时改它的

  塞字面量的话页面文案换了、组件库自己的文案还是旧语言。`i18n` 创建和 store 起效用的是

- **弹窗只有一种形态**：设置、构建日志、环境变量三个 el-dialog 都挂 `app-dialog` /
  `app-modal`（`style.css`）：垂直居中、标题固定、正文自己滚、遮罩带一层背景模糊、
  打开时锁住页面滚动。内容比视口高时如果让整个弹窗滚，标题和底部的操作区会一起滚出去，
  正文一滚就找不着自己在哪儿了。新加弹窗照抄这两个类，别再各写一套尺寸。
  高度分两档：默认**固定 90% 视口高**（正文区高度稳定，日志 / 环境变量这种一定超出视口

  - 2rem)`。标题是 Element Plus 的默认 18px（`--el-dialog-title-font-size`），
  **正文统一 14px**（日志弹窗里那个 xterm 的字号也是 14）。
  宽度分两档：桌面各按内容（640px / 78% / 46rem），**移动端统一 95%**——手机上按像素
  给宽度必然溢出。
- **保存不改变视图**：在源码视图里改完保存，仍然停在源码视图。编辑源码往往是一连串
  改动，存一次就被弹回表单只会让人再点回来。
- **首页（项目管理器）**：顶部工具条——搜索 / 新建 / 导入 / 图标，按钮和搜索框
  左对齐，右上角是显示方式切换（一个按钮，字面是当前那种，点一下换过去）。工具条固定

  create / import / remove 都在末尾 `await refresh()`，`ProjectActions` 的 rename /
  duplicate 也是这样），手点刷新只是多余的一次请求。

    **置顶**是纯界面偏好：状态只记在浏览器的 localStorage（`fpkstudio.pinnedProjects`，
    和主题 / 显示方式一样不进后端、不进 `state.json`），置顶的项目排在最前面、**先置顶的
    在前面**，标题旁边多一个图钉图标（否则「排前面」看不出是置顶还是巧合）。项目改名 /
    删除时置顶表跟着改名 / 删除，免得留下一条指向不存在项目的记录。排序是稳定的
    （`utils/pins.ts` 的 `sortPinned`）：没置顶的项目保持后端给的顺序，`check:paging` 钉住。
    **导出**的 zip 里带一层和项目同名的顶层目录（见下面「下载 / 导出」那条），解压出来
    不会把 `manifest`、`app/` 直接撒在用户选的目标目录里。
    **创建副本**先要一个副本项目名（不给默认值，留空或不合规时弹窗自己不让确认；重名也
    拒绝——后端 `Root.Copy` 对已存在的目标直接回 `ErrExists`、绝不覆盖，前端再查一次
    只是为了把提示写得更直白），然后复制整个项目目录，再把
    两处应用标识换成副本名：`manifest` 的 `appname`、`desktop_applaunchname` 的**前缀**
    和 `app/ui/config` 里 `.url` 每个入口 id 的**前缀**（入口 id 是 `<appname>.<入口名>`，
    只换第一个点之前那一段）。**其他文件原样复制**——图标、脚本、向导字段都跟应用标识无关，
    动了反而是错的。改写规则在 `utils/duplicate.ts`，`check:duplicate` 钉住；config 解析
    不了时不写回那份文件（只提示一句），免得拿残缺内容盖掉用户原来的文本。
  - **平铺**（默认）：`auto-fill` 按宽度自适应列宽，项目多了整页纵向滚。就是原来那个
    网格视图。
  - **分页**：为项目很多时准备的——一页正好铺满容器（列数按宽度、行数按高度算，见
    `utils/paging.ts` 的 `fitGrid`），**换页栏在顶栏那一块（工具条下面）**，`1 2 3 …`
    跟着窗口重算（钉在滚动区外面，项目区自己滚，页码永远在）。**每页几个跟着窗口走**：`HomeTab` 用 `ResizeObserver` 量项目区
    的内容尺寸（扣掉 `p-4` 的内边距）现算「几列 × 几行」，所以拉大窗口每页自动多放，
    缩小就少放；每页几个变小时原页码越界也不会弹回第一页（`clampPage` 退到最后一页）。
    分页网格的行高是 `1fr` 均分（卡片高度会差一行 mono 的完整项目名，按内容排会切掉
    最后一行），列数 / 行数走 inline style——拼出来的 `grid-cols-${n}` Tailwind 扫不到。
    只有一页时不显示页码。
  - **项目计数和称号在最后一行项目的下面**（居中共一行、上面一条分隔线，两种视图都有）：
    以前在顶栏，那位置更像「筛选结果」，放到底部才是「一共这么多」。称号按数量分六档
    （≤1 无名之辈 / ≤5 小试牛刀 / ≤10 渐入佳境 / ≤20 初入江湖 / ≤50 名扬天下 /
    更多打包之神；边界上的数量归下面那一档，映射在 `utils/paging.ts` 的 `rankKeyFor`，
    `check:paging` 钉住）。
    分页视图里这一行也在项目区**里面**，所以算每页几个时要把它一起扣掉（`footReserve`），
    否则一页会多出这一行、把最后一行卡片挤出去。
  这一页原来还有个「列表」视图（一行一个项目、宽屏横向分列）：两种排布在鼠标滚轮和
  滚动方向上各有一套规则，实际没人用，已经删掉（连同 `style.css` 的 `.list-columns`
  和首页那个 `wheelToHorizontal` 转发）。
  - 删除一定要过一遍确认弹窗（目录直接删，没有回收站）；重命名改的是**项目目录名**
    （`manifest.appname` 不动），如果这个项目开着标签，会关掉旧标签、按新名字重开一个
    ——所以有未保存改动时弹窗里会先提醒。两个动作都是「先改磁盘、再处理标签、最后刷列表」：
    刷列表会换掉 `v-for` 的 key、把这张卡片卸载掉，反过来做事件就丢了。
- **保存前拦格式错误**：`EditorApi.saveBlocked`（表单视图）和 `utils/validate.ts` 的
  `checkFormat`（源码视图）都会在写文件之前校验，格式不对就**只弹提示：不写文件、
  也不动编辑器里的内容**。两条路都要有——表单视图解析失败时模型是空的，直接存等于
  把用户的文件覆盖成一份空配置；源码视图能绕过表单直接写文本，一份写坏的 JSON 会让
  那个文件在 fnOS 里直接失效。认格式的只有这几类：manifest（有不是 `key = value`
  的行）、几份 JSON 配置（privilege / resource / app/ui/config）、向导，以及 i18n 的
  locale 文件（**官方是 INI 语法，不是 JSON**——早期这里把它当 JSON 判，结果是一份
  合法的 locale 文件在源码视图里根本存不进去，而它只有源码视图这一条路）；
  **生命周期脚本（cmd/*）和普通文本不校验**——脚本语法不该由这里说了算。
- **「未保存」判的是模型有没有被改过，不是文本和磁盘逐字节相等**：表单类编辑器的回写
  本来就会归一格式（JSON 的缩进与键序、manifest 补默认键），所以 `useEditor` 的基线取
  「磁盘上那份走一遍解析 + 回写」的结果——否则一份没编辑过的脚手架文件（fnpack 生成的
  `config/privilege` 是 4 空格缩进、结尾不带换行）一打开就算脏。切视图同理：表单不脏时
  交给源码视图的是**磁盘原文**，脏的时候才交回写结果，这样「切一下视图」本身不会凭空
  冒出未保存标记，两个视图的脏标记也才对得上（规则钉在 `scripts/check-editor.mjs`）。
- **图片打开就是预览**：`ImagePreview` 直接把下载地址交给 `<img>`（不读内容，省一次
  base64 编解码）。这一面**没有任何可存的内容**，工具栏的「还原 / 保存」直接藏掉
  （判据是 `registry` 里的 `previews` + 当前是表单 / 预览那一面）；svg 切到「源码」之后
  照常可以改、可以存。
- **编辑器按路径注册**：`src/components/editor/registry.ts` 把「路径正则 → 组件」
  集中管理，加一种文件类型只需要加一个组件和一行注册。已知的 fpk 配置
  （manifest / privilege / resource / app/ui/config / wizard / cmd）都有表单化编辑器，
  并且可以在「表单 ⇄ 源码」之间切换——切换是工具栏上的**一个按钮**，字面写的是当前视图
  （在表单视图里就写「表单」），点一下换到另一个；以前是两格的单选滑块，工具栏里只有它
  一种别的控件形态。源码编辑器（CodeMirror）**始终按宽度自动换行**
  （`EditorView.lineWrapping`）：配置和脚本里的长行横着拖很难读，窄面板和手机上尤其
  如此，所以桌面也一样换。
- **入口配置（`app/ui/config`）用一层标签**：入口不再是左侧竖排列表，而是编辑区上面
  的一层标签——窄屏上竖排列表会把表单挤到没地方，而入口本来就少、名字也短，横着排
  一眼看全。「新增入口」钉在**滚动区外面**（它是动作不是内容，标签滚到后面它也一直在），
  入口多到放不下时标签栏横向滚动：滚轮走 `wheelToHorizontal`，触摸靠 `.hscroll` 的
  `overflow-x` + `touch-action`；切 / 加入口会把选中项滚进可视区（`revealActive`）。
  删入口收在**标签上的 ×**（触屏常显、桌面悬停显示，和文件标签一致），所以表单里不再
  排一行「入口标题 + 删除入口」——那一行说的正是标签上已经写着的东西。删之前**要确认**
  （入口里可能填了一整屏内容，这一页没有撤销）。删的不是当前
  标签时不动选中项，删的正好是当前标签才顺势选前一个（否则删完别的入口，视线被莫名
  甩回第一个入口）。表单在桌面居中（`mx-auto max-w-2xl`，和其他编辑器一致）。
  表单里的两个复选框改成了开关（和 manifest 一个样式）。
  字段排布跟 manifest 那套一致（标题一行、控件一行、字号 14px、一行一组）：入口 ID / 标题、
  图标 / 打开方式、网关前缀 / 网关 socket 各一行，协议 + 端口占半行、路径独占另半行
  （路径比协议 / 端口长得多，平均分三列时它不够填），入口设置权限 / 所有用户可见 /
  在桌面隐藏 是三个一行的组，关联文件类型是多选、自己占一整行。窄屏下同样由 `form-stack`
  拆成一行一个，顺序就是 DOM 顺序——只有协议 + 端口那一对是嵌在单元格里的两列，不再往下拆。
- **资源声明（`config/resource`）分四块**（Docker 项目 / 共享目录 / 系统链接 / 飞牛 API
  调用列表），字段排布跟上面几份一致：标题一行、控件一行、字号 14px。每块右上角的 `+`
  加一条，行末的删除按钮**红色 + 贴右**（只有图标，所以照工具栏的规矩挂原生 `title`）。
  共享目录里「共享路径」只占半行，另半行留白；「读写用户 / 只读用户」上下分行、左右成对
  ——实际几乎只会填其中一个，各占一整行太浪费高度。系统链接的 bin / lib / etc 各是一个
  多选，placeholder 各举一个对得上类型的例子（`bin/myapp-cli` / `lib/myapp_lib.so` /
  `etc/myapp.conf`，同一个例子摆在 lib / etc 下面只会误导），大标题右边一句「app/ 目录下」
  说明填的是相对 `app/` 的路径。**API 授权项是开关，不再是勾选框**：标题 + 问号（功能描述
  收进问号里，不在标题下面铺一段；`trim.file.userAccess` 这类英文 id 不再显示），开关贴右；
  勾选状态就是那份 `api-scope` 数组（`setScope` 增删一项），新选的追加到末尾，写回文件的
  顺序就是用户选择的顺序。
- **环境变量弹窗**：生命周期脚本（`cmd/*`）的编辑页在「还原」左边有一个「环境变量」
  按钮，列出安装器注入的 `TRIM_*` 变量（按用途分组）、manifest 里的每个键、以及向导里
  收集到的字段（不带 `TRIM_` 前缀），点变量名即可复制。做法沿用 fnpackup 的
  「环境变量」页，只是从独立弹窗改成了挂在脚本编辑器上。
  「数据共享」那组除了裸变量，还有一段 `${TRIM_DATA_SHARE_PATHS%%:*}`——脚本里多数
  时候只要第一个共享路径，列表是冒号分隔的，`%%` 是最长后缀匹配，从第一个冒号起整段
  砍掉，剩下的正好是第一项。这种「变量上的 shell 展开」也按 `STATIC_GROUPS` 的 `vars`
  项写（渲染成 `${<项>}`，语言包键就是 `<项>` 本身）。
  另有一组「常用运行时」（`RUNTIME_ROWS`）：`export PATH=/var/apps/…:$PATH` 这种在
  脚本里挂 node / java / python 的整条命令。三条命令里的版本号都是占位符（`<version>`），
  复制走的就是**模板**，用户按自己机器上的版本改一下即可——所以能直接用的那一份实例
  **不作为可复制项列出来**，只在说明里点一句例子（`nodejs_v24` / `java-21-openjdk` /
  `python312`）。命令比弹窗还宽，行得能折行：复制按钮用 `min-w-0 break-all`
  （不能用 `shrink-0`——手机宽度下它会把弹窗撑出横向滚动），行本身是 `flex-wrap`
  （放不下时说明整块落到下一行；不然按钮把宽度占满，说明会被挤成一条 0 宽、竖着排字的
  列）。
- **向导编辑器**：字段类型覆盖 fnpack 的全部七种（text / password / radio / checkbox /
  select / switch / tips），校验规则支持一个字段挂多条（必填 / 范围 min-max / 长度 len /
  正则 pattern），新建步骤与字段会预填可用默认值（步骤标题、不重名的字段名、按类型给
  默认值），校验提示也有默认文案。每个表单项能上移 / 下移，顺序就是向导里的显示顺序
  （直接改内存模型，保存时按数组顺序回写）。
  字段卡片每个框都有**标题**（字段类型 / 字段名 / 字段标签 / 默认值 / 辅助文本），不再
  只靠 placeholder——填上内容之后就看不出哪个是哪个了。排布是「按钮一行 + 两行两列」：
  第一行左边是**字段序号 + 添加校验**（占一半宽度），右边是 ↑ ↓ 删除三个图标按钮（右对齐，
  间距收到 `gap-0.5` + `tree-tool` 内边距，免得并排时挤到卡片中间）；第二行
  **字段类型 + 字段标签**各占一半；
  第三行 **字段名 + 默认值**各占一半（字段名同时是脚本变量名，提示文字类字段这两格都没有）；
  再往下是单选 / 多选 / 下拉的**选项**（夹在默认值框和辅助文本框之间，它只影响那两个框里
  能选什么），最后是辅助文本（单独一行、会自己撑高，说明文字常常是一整段）。
  步骤头里**序号和步骤名算一组、占一半宽度**（右边留给「加字段 / 删步骤」两个按钮），
  字段卡片也一样带序号（`#1`、`#2`…，跟着上移 / 下移走）。
  向导文件顶部**不再重复写「向导文件：xxx」**：文件标签上已经写着它了。字段 / 选项 / 校验的
  删除按钮都是**红色**的，但只有**删步骤**会问一声（一个步骤里可能已经有整屏的表单项，
  字段 / 选项 / 校验只丢一行，逐条问会让人不敢动手）。向导文件**还不存在**时进来会先铺好第一步（带一个示例字段）：
  新建 / 刚导入的项目里这几份向导往往一个都没有，否则打开是纯空白、还得先点一下
  「添加步骤」；已经有内容的文件（哪怕内容是 `[]`）不动。安装 / 更新 / 配置三份向导
  往往就是同一套表单，工具栏的「覆盖其他向导」是一个下拉：选一份就把手上这份写进那一份，
  或者选「全部覆盖」一次写两份——一次改两个文件是破坏性的，不该是唯一的选择。
  覆盖是写磁盘的动作，所以写完后目标文件会被打开，能立刻看到写成了什么；
  目标文件不存在时这一步就是创建。解析与回写放在 `src/utils/wizard.ts`，和
  `manifest.ts` 一样单独成模块：不认识的键（fnOS 以后加的字段）原样保留，不会因为
  表单里没有对应控件就被删掉。
  **解析失败时保存会被拦住**（`EditorApi.saveBlocked`）：表单里那份模型是空的，
  存下去等于把用户的向导文件清空——那是不可逆的，宁可不让存，让人在源码视图里改回来。
  **「插入模板」按文件给**（`EditorHost` 的 `templateFor`）：没有通用模板的文件不显示这个
  按钮。`wizard/uninstall` 是卸载向导骨架——它收集 `wizard_data_action`，卸载回调脚本
  `cmd/uninstall_callback` 照着它决定删不删数据，两份是一套的，所以模板也配套给。
  `cmd/main` 是**启停脚本**，按项目类型给两份完全不同的模板（`utils/lifecycle.ts`，官方
  脚手架的原样文本，别顺手「优化」写法）：非 docker 由脚本自己托管进程（pid 写进
  `${TRIM_PKGVAR}/app.pid`、日志追加到 `info.log`、TERM 之后等 10 秒再 KILL、status 返回
  0 / 3）；docker 应用是应用中心拉起的容器，start / stop 直接 `exit 0`，只有 `status`
  去 `docker inspect` 那个 `container_name`。判据是 `ProjectInfo.docker`（后端按
  `app/docker/docker-compose.yaml` 是否存在判定，从 `workspace` 的状态读，项目标签打开时
  它一定已经就位）。给错的表现很隐蔽：脚本语法没问题，但应用中心里「启动」点了没反应。
  `${...}` 在这种模板字面量里**少转义一个反斜杠就会被当插值吃掉**，所以 `check:editor`
  钉住两份模板的归属、变量写法和关键语句。
  `i18n/en-US` 与 `i18n/zh-CN` 给的是**官方文档那份 locale 示例去掉值**（section / key
  全留着、值留成空的双引号，`utils/i18nFiles.ts`）——少一个键，用到它的那个字段在
  fnOS 侧就取不到值。**其他语言不给模板**（文档只点名要求 en-US，按钮照常不出现）。
  顺带一条官方约定：项目里有 `i18n/` 目录就**必须**有 `en-US`，缺了界面提示、`Pack`
  也会拒（后端 `checkI18nLocale`）——判据是纯函数，`check:editor` 钉住。
- **manifest 回写保持原样**：`src/utils/manifest.ts` 逐行记住原文件（含注释、
  空行、对齐风格），只改动真正被编辑的键；`"""多行值"""` 会被正确识别。
  官方 fnpack 的模板是对过齐的，直接按行重排会让 diff 没法看。
  表单里「清空 = 不声明」这条语义由 `compact` 落实：安装位置选「存储位置」时
  `install_type` 会被删掉（而不是留一个空值），选「系统分区」写 `install_type=root`。
  界面上「存储位置」用一个哨兵值（`ManifestEditor` 的 `INSTALL_STORAGE`）而不是空字符串
  ——el-select 对空字符串会显示成占位符，看着像没选；读写模型时它和空字符串互转，
  不会漏进用户的 manifest。没声明 `install_type` 的项目打开就是选中「存储位置」。
  链接（maintainer_url / distributor_url）和更新说明（changelog）跟描述一样是会自己长高的
  多行框——它们本来就可能很长，单行输入框只会把内容藏起来。
  **「默认入口」是可输入 + 可选的下拉**：候选是 `app/<入口目录>/config` 里 `.url` 的键
  （入口 id 只存在键名里，见 `utils/entries.ts`），**每次点开下拉都现读一次磁盘上的那份
  config**——用户常常先在「入口配置」里加一个入口，回来才填默认入口，读编辑器里那份缓存
  会拿不到刚加的；当前值也会并进候选，否则一个 config 里暂时不存在的 id 会被显示成空的、
  一保存就丢。读不到就当没有候选（照样能手输），不弹错。入口目录取同一行里 `desktop_uidir`
  的值（默认 `ui`）。
  「依赖应用」给了一份预选名单（`ManifestEditor` 的 `DEP_APP_PRESETS`，一行一个应用标识），
  但**不限制手输**：这个字段仍然是 allow-create + filterable，下拉只是省得敲；
  候选 = 预选 + 已经选中的自定义值（只列预选的话，manifest 里自己敲进去的标识在候选里
  等于不存在，看不到它已经选上了）。
  下拉限高 3 行、内部滚动（`.dep-apps-popper`，在 `style.css` 里）：候选有四十来项，
  全展开会盖住大半个表单。
  表单在桌面上按「一行一组、组里每个字段标题一行 + 控件一行」排：标识 / 显示名称、
  版本 / 架构、开发者 / 发布者（同行的是同一种控件，输入框宽度才对得上）、
  开发者链接 / 发布者链接、最低 / 最高系统版本、安装位置 / 服务端口、
  入口目录 / 默认入口各占一行，依赖应用和四个开关各一行，描述和更新说明各自一整行；
  标题和控件字号统一 14px（Element Plus 全局配的是 `small` = 12px，这几个控件显式给
  `size="default"`，`TagSelect` 也因此多了一个 `size` 透传）。分组就是字段表本身
  （`ManifestEditor` 的 `rows`，内层数组 = 一行），
  **列数按组里的字段个数算**，所以别把类名拼成 `grid-cols-${n}`——Tailwind 扫的是源码
  里的字面量，拼出来的名字不会进产物。窄屏下 `form-stack` 会把每行的分组拆开。
  **「来源」不在表单里**：包都是第三方的，这个值改不了也没必要改，所以既不显示也不回写
  （`source` 仍留在 `KEEP_WHEN_EMPTY` 里，免得 `compact` 顺手删掉用户文件里那条空值行）。
- **多选下拉的标签：宽度够就全显示，放不下才折叠**（`components/editor/TagSelect.vue`）。
  `el-select` 的 `collapse-tags` 是**按个数**折叠的（`max-collapse-tags`，默认 1），
  不看容器多宽——600px 宽、四个短标签的字段也会显示成「第 1 个 +3」。所以这个控件每轮
  排版都量一次标签的真实宽度，用 `utils/tags.ts` 的 `fitTagCount` 算出放得下几个再交给
  `el-select`；宽度变化靠 `ResizeObserver` 跟（桌面 / 移动布局、被 v-show 藏过的标签页）。
  量宽度前会把标签全部渲染出来（折叠掉的标签不在 DOM 里，量不到），所以一轮排版有两次
  渲染，都在同一个微任务队列里跑完，浏览器还没绘制。两处刻意的取舍：初值取「一个都不
  折叠」而不是 1（否则首帧闪一下 +N）；算「放得下几个」时要扣掉行末输入框的最小宽度
  （11px + gap，和 `el-select` 自己的 `tagStyle` 一致），否则点一下输入框标签就折行了。
  用它的地方：manifest 的「依赖应用」、向导里 `checkbox` 字段的默认值。
- **同一份产物挂任意 baseURL**：构建时 `base: './'`，服务端返回 index.html 时
  注入 `<base href>` 和 `window.__FPKSTUDIO__`。换挂载点不需要重新构建。
- **静态资源的缓存分两档**（`internal/server/static.go`）：`assets/` 下是 Vite 带内容哈希
  的 chunk 与 css，回 `Cache-Control: public, max-age=31536000, immutable`，升级换名字、
  不会取到旧代码；其余（index.html、固定名字的文件）一律 `no-cache` 回源确认，index.html
  还是 `no-store` + 每次都重新注入 base href——**升级之后必须能拿到新页面**，而几 MB 的
  包体不该每次刷新都重下。判据用的是去掉前导斜杠的相对路径（`assets/xxx.js`），别写成
  `/assets/`（根目录这份匹配不上，表现是「加了缓存头但资源还在回源」）。
- **十一个检查脚本**（`npm run check`，需要 Node ≥ 23.6，用到默认开启的类型剥离）：
  - `check:i18n`：两份语言包的每条消息都能被 vue-i18n 编译、键完全一致。消息里的 `{`
    是插值语法，一句带 `${...}` 的提示会让这条消息在 `t()` 时抛错——而且是在渲染到
    那个组件时才抛，表现是「弹窗整体画不出来」，所以让它在这一步就被挡住。
  - `check:wizard`：`utils/wizard.ts` 的解析 / 回写往返（真实 fpk 向导、七种字段类型、
    四种校验、不认识的键要保留）。这段逻辑会重写用户项目里的文件，值得盯住。
  - `check:icon`：取景框的几何——初始铺满居中、拖到任何位置都不露空白、以指针为锚
    缩放、取景框对应的原图矩形始终在图片范围内，以及裁剪 / 圆角 / 导出的参数；
    另外盯住副入口图标的两件事：前缀不会跑出 `app/ui/images/`（前缀直接拼进文件名），
    以及目录里已有的 `<前缀>_64/256.png` 能不能被正确认成副入口（只认 64 / 256、
    排掉默认入口 `icon`、只有一个尺寸也算）。
  - `check:format`：`utils/format.ts` 的 `uniqueName`（粘贴时挑不重名的那个名字）。
    它算错的表现是「粘贴把已有文件覆盖掉」，所以值得单独盯住。另外盯 `manifest` 的回写：
    没编辑过的内容（对齐、缩进、注释、多行值）必须原样写回，只有被改过的值才允许变；
    以及 `checkFormat` 对 i18n 的 locale 文件按 **INI** 判（合法的要放行、会静默失效的
    要拦住）——判成 JSON 的表现是「一份好好的 locale 文件存不进去」。
  - `check:tags`：`utils/tags.ts` 的 `fitTagCount`（多选下拉一行能放下几个标签）。
    它算多的表现是标签折到第二行，算少的表现是明明有位置却白折叠一个——两种都是一眼
    能看出来、只看代码看不出来的错。
  - `check:paging`：`utils/paging.ts` 的 `fitGrid` / `clampPage`（首页分页视图一页放几个
    卡片、页码越界退到哪一页）。差一个间距的表现是「底部那排卡片被切掉一半」，只在特定
    窗口尺寸下出现，光看代码看不出来。
  - `check:duplicate`：`utils/duplicate.ts` 的 `replaceEntryPrefix` / `rewriteForDuplicate`
    （创建副本时把 manifest 与 app/ui/config 里的应用标识换掉）。算错不会报错，只会让副本
    「看着正常但用不了」——入口点不开、或者和原项目抢同一个应用标识。
  - `check:semantic`：`utils/semantic.ts` 把「请求了哪几条路径」和 `trim.file.convertPath`
    返回的条目对上号（尾斜杠归一、顺序一致时按位置兜底）。它错了的表现是设置弹窗里
    「语义路径不显示、退回 /vol1/...」，而且不报错，所以值得单独盯住。
  - `check:workspace`：文件管理器 store 里「会丢 / 写坏用户文件」的三条路径——重命名一个
    打开着的文件（标签跟着改名，内容基线 / 脏标记 / 草稿都不能丢）、重命名目录（里面的
    子标签一起改，否则保存会照着旧路径写回一个「复活」的文件）、重名与非法名字必须拒绝。
    在 node 里跑真实的 store，后端用一个内存文件表顶替。
  - `check:editor`：表单编辑器的「未改动」判据、切视图该交哪份文本（`utils/handoff.ts`），
    以及「插入模板」的文本（`utils/lifecycle.ts`、`utils/i18nFiles.ts`）——包括 i18n 的
    locale 模板（section / key 齐不齐、值有没有留空）和「缺 en-US」的判据。
  - `check:logs`：日志 store 的去重游标与补历史（后端重启后 `lastSeq` 要归零、补历史和
    实时帧按 seq 合并）。错了的表现只是「日志不动了」，数据其实没坏，所以单独盯住。

## HTTP API

所有接口都在 `${BASE_URL}api/` 下。`path` 参数一律相对**项目根目录**——也就是
`projects/` 这个沙箱根（不是某一个项目），所以写法是 `<项目名>/app/...`。
返回里的路径（例如解压结果的 `dir`）用的是同一套写法。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/system/info` | 版本、目录、socket、fnpack 探测结果 |
| GET | `/api/projects` | 项目列表（`GET` 之外的方法回 405，所有写接口同理） |
| GET | `/api/projects` | 项目列表 |
| POST | `/api/projects/create` | `{name, docker, ui}` → 调 `fnpack create`；项目名需 3–32 位、字母数字开头结尾，中间可含 `. _ -` |
| POST | `/api/projects/delete` | `{name}` |
| GET | `/api/projects/exists?name=` | 是否存在、是否 docker、是否有桌面入口 |
| GET | `/api/projects/platforms?name=` | `building/platform/` 下的架构目录 |
| GET/PUT | `/api/projects/settings?name=` | 打包偏好（`platforms` 始终是数组，不会返回 `null`） |
| POST | `/api/projects/import` | multipart 上传 `.fpk`（**上限 1G**，超了回 413；可取消），解包成项目 |
| POST | `/api/projects/pack` | `{name, platforms[], serverDir, copyOut}` |
| GET | `/api/projects/artifacts?name=` | 产物列表（项目内 + 输出目录） |
| GET/POST | `/api/fs/list?path=` | 目录列表，`path` 也可以放在 JSON body 里（前端就是这么调的） |
| GET/POST | `/api/fs/read?path=` | 读文件（二进制会返回 `text:false`，不带内容）。**超过 8MB 的文件只回元信息**（`tooLarge:true`，`content` 为空），界面给「下载后用本机编辑器改」的提示 |
| POST | `/api/fs/write` | `{path, content}`（`GET`/`PUT` 也收，前端用 POST） |
| POST | `/api/fs/create` \| `delete` \| `rename` \| `copy` | 文件操作；`create` **文件已存在时拒绝**（不会把已有文件清空），目录仍是幂等的 `mkdir -p`；`rename` / `copy` 目标已存在时也拒绝 |
| POST | `/api/fs/upload` | multipart（`path` / `overwrite` / `file`）；`overwrite=false` 时**跳过**已存在的文件（响应里给 `skipped`），`true` 才覆盖。**单个请求上限 1G**（超了回 413），客户端断开 / 取消时服务端跟着停、半截文件删掉；打包落地目录（`serverDir`，默认 `app/server`）下的文件按 0755 落地，其余 0644 |
| POST | `/api/fs/extract` | `{path}` → 解压到压缩包所在目录（系统 tar / unzip / gzip），返回 `{kind, dir, files, skipped, links, specials}`；同名文件跳过不覆盖；符号链接与 FIFO / 设备节点都不还原（`links` / `specials` 是丢掉的个数）；归档本身必须是沙箱里的普通文件（符号链接会被拒绝）；一次解压有 10 分钟上限 |
| GET | `/api/fs/download?path=` | 下载文件，目录会打成 zip（包内带一层同名目录） |
| GET | `/api/logs?after=&limit=&source=` | 增量拉日志；响应里的 `boot` 是后端进程标识 |
| GET | `/api/logs/stream?after=` | SSE 实时日志；第一帧是 `event: boot`（带进程标识与 `lastSeq`），前端靠它判断「后端换进程了、去重游标要归零」 |
| GET/PUT | `/api/settings` | 目录设置（`{projectRoot, outputDir}`，空字符串 = 回默认）；GET 还会带上当前用户与飞牛接口可用状态。**PUT 的权限判据**：经过统一网关时要求管理员（`X-Trim-Isadmin`），且新目录必须在本应用被授权的目录里（开放 API 可用时判）；直接调 socket（没有网关）时保持原行为——那种部署下 socket 权限就是边界 |
| GET | `/api/trim/status` | 飞牛开放 API 的可用状态 + 当前用户 |
| GET | `/api/trim/folders` | 当前用户授权给本应用的目录 |
| POST | `/api/trim/folders/delete` | `{path}` → 删除一条目录授权 |
| POST | `/api/trim/acl` | `{paths[]}` → 当前用户对若干路径的读 / 写 / 删权限 |
| POST | `/api/trim/semantic` | `{paths[]}` + `?language=` → 语义化路径（`/vol1/...` → 存储空间1/…） |
| POST | `/api/projects/import-path` | `{path}` → 导入本机某个绝对路径上的 fpk（飞牛文件选择器选的）；包本身**上限 1G**（这条没有请求体可卡，按文件大小判） |

**状态码语义**：目标不存在 = 404（前端按「还没创建」处理），路径不合法 / 目标是目录 /
目标已存在 = 400 / 409，没有权限 = 403，请求体或上传超限 = 413，方法不对 = 405，其余才是 500。
`path` 里的 `..` 会被拒绝（400），越界的写法不会静默改写。

`/api/trim/*` 与 `/api/projects/import-path` 都按**飞牛统一网关转发的用户**判权限
（`X-Trim-Userid`，见下节），没经过网关时退化成后端进程自己的 uid。

```
│       ├── fnpack/             fnpack 调用与输出转发
│       ├── projects/           项目列表、创建、导入、多架构打包、产物、可切换的项目根
│       ├── state/              数据目录下 state.json 的读写（项目根 / 输出目录）
│       ├── trimapi/            飞牛开放 API 客户端（只走 unix socket 的服务端接口）
│       └── server/             HTTP 路由、静态资源、各项 API（含 /api/trim/* 的转发）
└── frontend/                   Vue 前端（Vite 产物到 frontend/dist）
    ├── src/
    │   └── trim/               飞牛 JS SDK 的封装（环境判断、选择器、宿主主题）
    └── dist/                   构建产物，被复制进 backend/embed
```

`backend/embed`、`frontend/dist`、`frontend/node_modules`、`./fpkstudio` 以及
Makefile 用的本地缓存目录都在 `.gitignore` 里，仓库里只留源码。

首页的项目操作（重命名 / 导出）没有专门的接口：重命名就是把项目目录当普通目录改名
（`/api/fs/rename`），导出就是下载这个目录（`/api/fs/download` 对目录打 zip）。
换句话说，项目目录本身就是项目，没有另一份元数据要同步——`manifest.appname` 是
应用标识，改目录名不会动它。

## 实现上值得说明的几处

- **多架构出包**。`building/platform/<架构>/` 存各架构的产物，打包时把它复制到
  `app/server`、把 `platform` 写进 manifest，每个架构出一个 fpk。包里带了架构相关的
  东西却写 `platform=all` 是最常见的翻车点——应用中心会把它装到不匹配的设备上然后起不来，
  所以编辑器在检测到「`platform=all` 且项目里已经有架构目录」时会给出提示。
  新建项目时预置 `arm` / `x86` 两个目录；导入的 fpk 里只有打包后的 `app/`，没有这套
  工作目录，所以导入后也补上（同一份 `platformDirs`），前端在打开「多架构发布」开关时
  再兜一次——补充见 `backend/internal/projects/import_test.go`。
- **不修改用户的项目文件**。fnpackup 是原地改 `manifest.platform`、覆盖 `app/server`
  再打包，打一次项目就脏了。这里把项目整体复制到 `tmp/build-*`，在副本上改、在副本上
  打包，结束删掉；`fsx` 的复制会把权限位显式 `chmod` 一遍。
  **进包的那份 manifest 还会去掉格式用的空格**（`stripManifestSpaces`，在 `Pack` 里对着
  暂存副本跑一次）：`appname   =   demo  ` 收成 `appname=demo`。值内部的空格一个都不动
  （`display_name = My App` 的 `My App` 是内容），`"""` 多行值的正文整段跳过，空行与注释
  留着、只去行尾空白。判据和解析器对齐（同样按第一个 `=` 切、同样跳过没闭合的多行段），
  所以键值一个都不变；用户项目里那份 manifest 保持原样（还是官方模板那种对齐写法）。
  格式化失败只记一条日志，不因此让整次打包失败（真读写不了，fnpack 那步会自己报）。
  回归在 `internal/projects/pack_test.go` 的 `TestPackStripsManifestSpaces`。
- **权限位显式设置**。飞牛的存储卷上，新建文件会继承父目录的模式位、`open(O_CREAT, mode)`
  的 mode 参数被忽略；实测新建文件会落成 `0000`，这种文件打不进 fpk（fnpack 会在复制
  阶段 `EACCES` 失败）。所以写文件、复制、上传后都会显式 `chmod`。
- **`TMPDIR` 固定到数据目录**。fnpack 会先把整个包复制到临时目录再打包，
  `TMPDIR` 跨挂载点或落在受限的 `/tmp` 时会直接失败。
- **项目根目录可以被换成授权目录**。默认值来自环境变量，改过之后记在数据目录的
  `state.json`，启动时应用一次（打不开就沿用默认目录并记一条日志，不让一个过期的路径
  把服务拖住起不来）。项目根落在数据目录之外时，打包前的暂存复制跨了两个沙箱：单靠
  任一个 `fsx.Root` 的相对路径都表达不了，改走 `fsx.CopyTree` 的绝对路径复制；导入时
  从暂存区搬进项目根也同理，先试 `rename`（同文件系统瞬时完成），跨设备 `EXDEV` 时
  退回复制 + 删源。
- **`os.Root` 做沙箱**。所有文件操作都在 `os.Root` 内进行，逃逸（`../`、指向外部的
  符号链接）在 `openat` 层面被拒绝，不依赖字符串前缀检查。
- **解压交给系统 `tar` / `unzip` / `gzip`**（按需求），默认写死 `/usr/bin`（服务进程的 PATH
  不保证有 /usr/bin，而飞牛上这些工具就在那儿；文件不在才回落到 PATH 查找），不给它们加
  环境变量。这些工具都没有「不许写到目标目录之外」的可靠开关（tar 只警告、退出码 0；
  `unzip` 把越界名字截断后照写），所以解压前先自己列一遍成员名（tar 用 `tar -t`、
  zip 用 `unzip -Z1`），含绝对路径或 `..` 段的归档整体拒绝；再解到目标目录里一个本次请求
  独占的暂存目录，丢掉里面的符号链接，最后逐个 rename 就位、同名跳过。整个过程不会碰
  用户已有的文件。
- **日志一条都不丢**。日志同时进文件、内存环和 SSE 订阅者；订阅者通道满了就丢那一条，
  绝不阻塞业务（打包输出走的就是这条流）。分发和「订阅者退订」用的是同一把锁——
  退订会 `close(ch)`，而向已关闭的通道发送即使带 `default` 也是 panic，早先分发在锁外
  做的时候，SSE 客户端断开的瞬间正好有人在写日志，整个进程就挂在 `send on closed
  channel` 上（`internal/logging/logging_test.go` 钉住了这一条）。
- **单实例保护**。启动时先试着连一下 socket：连得上说明已有实例在跑，直接拒绝启动；
  连不上才当残留文件清掉。退出时只删自己那个 socket（比对 inode），不会误删新实例的。
- **构建产物清理**。fnpack 模板自带 `.DS_Store`，在部分文件系统上会让 `fnpack build`
  直接失败，所以创建和导入项目后都会清掉这些文件。
- **产物文件名只由受校验的成分拼成**。产物叫 `<appname>-<version>-<platform>.fpk`，三个
  成分都来自 manifest（用户能随便写，导入的 fpk 更是别人给的），所以拼之前按「一个文件名的
  成分」逐个校验（不含分隔符 / 控制字符、不是 `.` 或 `..`、长度有上限）；落地走
  `fsx.Root.WriteReader`，不用绝对路径拼——`filepath.Join` 会把 `..` 规整掉，
  `version = ../../x` 这种值能让产物写到项目根之外。`serverDir` 同样不许填 `.`
  （那会把整个暂存项目连同 manifest 一起替换掉）。
- **解压结果里只有普通文件与目录**。归档成员名先校验（绝对路径 / `..` 直接拒绝），解到本次
  请求独占的暂存目录，然后把**符号链接与非普通文件**（FIFO、设备节点）都删掉再逐个
  `rename` 就位。链接会指向归档之外（打包 / 导出时被顺着读出去）；FIFO 更直接——没有写者时
  `open(2)` 一直阻塞，留在项目里之后每次读它都会永久占住一个 goroutine 和一个子进程。
  交给外部命令的是绝对路径，`os.Root` 在这一步帮不上忙，所以**归档本身也必须是普通文件**
  （指向沙箱外的符号链接会被拒绝）。
- **读、上传、解压都有上限**。`/api/fs/read` 超过 8MB 只回元信息；上传 / 导入单个请求
  1G（`http.MaxBytesReader`，以前只给了 `ParseMultipartForm` 一个内存阈值，总量不设限时
  超出的部分会落进程 TMPDIR，一直传就能灌满盘）；解压给 10 分钟上限并把请求的 ctx 传下去，
  客户端断开时子进程被杀掉。上传与导入都支持取消：前端 abort，后端的写入用
  `ctxReader` 立刻退出、半截文件删掉。
- **日志环按配置的上限裁**。上限单独存成 `ringMax`，不能拿 `cap(l.ring)` 当上限：`append`
  会先把容量翻倍，于是 `len > cap` 在 append 之后永远不成立——那段裁剪曾经是死代码，
  日志环实际上从不封顶（`internal/logging/ring_test.go` 钉住了这一条）。

## 已知限制

- 没有鉴权（按需求）。请依赖 socket 文件权限，以及你自己套在外面的反代。**注意**：这套 API
  的读写范围 = 「应用用户在文件系统上的权限」，不是「当前登录用户的权限」；改目录设置这一条
  已经加了管理员 + 授权目录两道判据（见上面的 API 表），其余的接口只认 socket / 你套的反代。
- 后端的错误文案是中文的（界面文案才有中英双语）：英文界面下，来自后端的错误（读写失败、
  fnpack 的输出等）会以中文显示。要做完整本地化得给每个请求带语言、给所有文案加键。
- 图标页的「小图」默认按工作尺寸导出（默认 256×256），文件名仍是 `ICON.PNG` /
  `<前缀>_64.png`；想跟文件名对上，把「小图缩放」改成 1/4（64px）。
- 打包是同步请求，超大项目会让这个 HTTP 请求长时间不返回；日志通过 SSE 实时输出，
  前端不会卡住，但打包请求本身没有超时控制（读 / 上传 / 解压有，见上）。
- 下载目录（`/api/fs/download?path=<目录>`）会先把 zip 打进数据目录下的临时文件再发正文：
  这样「某个文件读不了」能回一句错误，而不是发一个里面是 0 字节条目的残包。代价是下载期间
  多占一份临时空间。zip 里**保留一层和目录同名的最外层目录**（`fsx.ZipDir`，项目导出走的
  也是这条路）：解压出来独占一个目录，不会把 `manifest`、`app/` 直接撒在用户选的目标里；
  空目录也会留下这一个目录条目（少它就得到一个没有任何成员的「空包」，解压工具直接报错）。
  只有下载**沙箱根**（`path=.`）时没有名字可取，那一层就省掉。
  **下载 / 导出目录时会挂一条不自动消失的「正在打包下载」提示**（`useDownload` 的
  `zip: true`）：压缩是在后端做的，稍大的项目要等几秒，不给提示用户会以为没点中、于是
  再点几次（每次都在后端排一份压缩）。提示拿到响应（或失败）时关掉；**单文件下载不提示**
  ——它几乎是瞬时的，弹一条随即消失的提示只会闪一下。
- 没有项目级别的并发保护：同一个项目同时触发两次打包，第二次会等在暂存区复制之后，
  结果是两份产物互相覆盖（不会污染项目本身）。
- `wizard` 编辑器的表单不呈现「认识之外的键」（例如 fnOS 以后新增的字段），
  但它们会原样保留、保存时写回；界面上只列一下键名，避免误以为被删掉了。
- 向导的取值校验（范围 / 长度 / 正则）只是编辑器侧的字段约束，最终仍以 fnOS
  安装器的行为为准。
- 解压只认上面列的那批后缀，且**同名一律跳过**、**符号链接不还原**：
  想用压缩包里的版本覆盖项目里已有的同名文件，得先自己把旧文件删掉。解压也只会刷新
  压缩包所在的那一层目录，更深的子目录里如果已经展开过，那份列表要等下一次刷新。
- 重命名**不覆盖**已存在的同名文件（直接报错），也不会把文件搬进子目录——名字里带
  `/` 会被拒掉。要在目录之间搬文件，用「剪切 + 粘贴」（store 里是 `moveEntryAt`，
  和 `renameEntryAt` 是两条路：后者只负责同目录改名）。
- 移动布局是同一套组件换排布，不是另一套页面：切换时项目里的编辑器宿主会被重建，
  编辑器里没保存的内容靠 `FileTab.draft` 接力（重新挂载后接着编，脏标记也对得上），
  但「表单 / 源码」的视图选择会回到表单——这一点和切标签不一样。
- UI 只做了中英双语，语言按浏览器 `navigator.language` 选择，没有做切换入口（主题倒是
  可以在设置里切）。
- 文件选择与授权类能力只在飞牛宿主页面里可用。用 `socat` / 反代直接打开时没有这些入口，
  相关按钮置灰并提示原因。
- 用户身份取网关转发的 `X-Trim-Userid`；直接调 socket（没有网关）时用的是后端进程自己的
  uid，多用户场景下查出来的授权与 ACL 不一定对。要做多用户，得按官方建议把应用挂到统一
  网关下。
- 目录设置改到授权目录之后，已有项目**不会自动迁移**：改回默认目录就是换一个地方找项目，
  文件还留在原来的位置。
- 换目录时靠「选之前 / 选之后的授权列表做 diff」确定用户选了哪个目录。diff 不出唯一的新增项
  （例如重选了一个已经授权过的目录）时会拒绝这次变更并提示——猜错的代价是项目根整个换地方、
  旧授权被删掉，不值得赌。
- 后端重启之后日志弹窗会继续工作（靠 SSE 的 `event: boot` 把去重游标归零），但重启期间
  （日志环形缓冲之外）的输出看不到。

## 构建环境说明

Makefile 把构建期需要的环境变量都收敛到项目本地目录，`make` 不需要你额外设置任何东西：

| 变量 | 默认值 | 为什么需要 |
|---|---|---|
| `GOCACHE` | `./.gocache` | 有些环境里 `$HOME` 下的缓存不可写，`go build` 会报 `package fmt is not in std` 这类误导性错误 |
| `GOPATH` | `./.gopath` | 同上 |
| `TMPDIR` | `./.tmp` | `go build` 的 `$WORK` 走 `os.TempDir()`；`/tmp` 受限时会报 `open /tmp/go-build.../exe/a.out: permission denied` |
| `CGO_ENABLED` | `0` | 纯 Go 程序不需要 cgo；关掉后产物静态链接，而且冷编译不再走 `runtime/cgo`（那一步会写 `.o` 中间文件，在某些存储卷上会被损坏） |
| `GOFLAGS` | `-buildvcs=false` | 仓库可能没有 `.git`，不必因此失败 |
| `PATH` | 前置 `/var/apps/nodejs_v*/target/bin` | fnOS 上 Node 由应用提供，不一定在 `PATH` 里；取版本号最高的一个，可用 `NODE_BIN=` 覆盖 |

这些都是 `?=` 或追加式赋值，**环境里已有的值优先**，所以放进 CI 或别的构建机也能用。

两个只在特定文件系统上才会踩到的坑，Makefile 里也处理了：

- 复制前端产物用的是 `tar` 管道而不是 `cp -r`。飞牛的存储卷不兑现 `mkdir` 请求的
  模式位，`cp` 生成的目录会落成 `0000` 且丢掉继承来的 ACL，`go:embed` 直接报
  `pattern all:embed: permission denied`；`tar` 解包后会显式 `chmod` 目录，结果才可用。
- 编译后显式 `chmod 755` 二进制。同一个原因——新建文件的模式位不可靠，
  不补这一下拿到的是个跑不起来的 `0000` 文件。
